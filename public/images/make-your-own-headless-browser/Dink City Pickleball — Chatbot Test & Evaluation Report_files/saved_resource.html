The brief

Four rules the bot must never break

Members will ask it anything. The job was a bot that stays helpful and on-brand without ever inventing a price, a time, or a program that isn't real.

Grounded

Only the club's data

Every answer comes from the schedule. No invented programs, prices, coaches, or times — ever.

Warm

Short & friendly

Two or three sentences, always welcoming. It sounds like your front desk, not a manual.

Honest

Knows its limits

If the schedule can't answer it, the bot says so and points the member to the front desk.

Focused

Stays on topic

Anything that isn't about the club gets a polite decline and an offer to help with club questions.

How the testing works

Every answer is graded, automatically

Each test question runs through the bot and its answer is scored against a plain-English rule. Nothing passes on a hunch.

Step 01

Member asks

A real question — a price, a time, or something designed to trip the bot up.

Step 02

Bot answers

The top model, claude-sonnet-5, replies using only the club schedule.

Step 03

A judge grades it

A second model checks the reply against a plain-English rule for that question.

Step 04

Pass / fail

Every result is logged. A green board means the bot held up on all fronts.

Why two different models? Grading an answer is far easier than writing one — so the answers come from a premium model while a cheaper, faster one (claude-haiku-4-5) does the grading. Same rigor, a fraction of the cost each time you re-run the suite. A small custom connector also keeps the top model running clean by skipping a setting some tools still send by default.

The road to 14/14

We hardened the test, not the bot

The chatbot's answers were correct from the very first run. Every early "failure" was the grader being too strict in a way it shouldn't be — so each fix sharpened the test itself.

1
9 / 14First run

The grader was checking facts it couldn't see

The judge was asked to confirm answers against a schedule it was never given, so it failed correct answers by default.

Fix — the judge now grades tone and length; factual accuracy is checked question-by-question against a known answer key.

2
13 / 14Second run

One check still tried to second-guess a right answer

A single fact-check asked the judge to independently verify a correct time — which it couldn't — so it hesitated and failed a good answer.

Fix — every fact-check now treats the known-correct value as the answer key and simply confirms the reply matches it.

3
14 / 14Final run

Green across the board

With the test suite sound, all four categories passed — proving the bot answers accurately, defers honestly, clarifies when vague, and declines off-topic asks.

Two judgment calls

Where we adapted to your real data

Adaptation

One location, so ambiguity is about time

The brief imagined "which location?" questions, but every session is in Holyoke. So the vague-question test asks "when is open play?" — and expects the bot to ask which day and skill level rather than guess.

Adaptation

A lean, lower-cost grader

The brief suggested grading with the same premium model. We used the cheaper Haiku model as the judge instead — identical results, meaningfully lower cost per run. A one-line change if you'd prefer the premium grader.
